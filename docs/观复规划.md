## 0. 结论摘要

- `~/Git` 共 **27 个仓库**，其中 **19 个具备机器可读的数据出口**（REST / RSS / 导出 / MCP / CalDAV）。
- 观复六大目标数据中，**4 类已有成熟数据源**：记账（huozhi）、演出（mujian）、日记（diarum）、健康指标（zhichang）。
- **2 类缺口均已解决（v3）**：**到访地点**——复用 Dawarich（REST API 只读消费，`/api/v1/timeline`、`/api/v1/visits`）；**拍摄的照片**——接入 Immich（`https://immich.example.com`，v3.3.1），2026-10-15 实测 key 有效、照片可达（2 张测试资产在线）、`asset.read/view/download/statistics` 等读取权限齐全。
- **yuexi（月汐）经决策不接入**（原计划因 cookie-only 认证需 0.5-1 人日改造，现整体移除，相关改造与导入过渡方案一并取消）。
- 前端选型已确认：**SvelteKit 5**。
- 观复自身沿用既有技术范式：**Go 1.27 单二进制 + 纯 Go SQLite + 前端构建内嵌 + Docker 单容器**，与全家桶 20+ 个仓库保持一致。

## 2. 观复应用架构

### 2.1 定位与技术选型

**定位**：本地/内网部署的个人生活数据聚合器——按「天」把多源事件汇成一条时间轴，不做社交、不做云端。

**技术选型**（与既有全家桶一致，降低维护成本）：

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Go 1.27 + chi + log/slog | 与 mujian/zhichang/qiansi 一致 |
| 数据库 | SQLite（modernc.org/sqlite，纯 Go 无 CGO）+ WAL | 全家桶统一；单文件易备份（复用 docker-db-auto-backup） |
| 前端 | **SvelteKit 5（已确认选型）** + Tailwind v4 + ECharts 6 + Leaflet，静态产物 `go:embed` 内嵌 | 与 mujian/diarum/zhichang 同范式，时间轴/日历/地图/图表四类视图均有现成实现可借鉴 |
| 部署 | 单容器 Docker（amd64/arm64），数据卷挂 SQLite | 全家桶统一模式 |
| 通知（可选） | ntfy（自建） | 同步失败/异常推送 |

### 2.2 模块划分

```
guanfu/
├── cmd/guanfud/main.go        # 入口：serve / sync / mcp / import 子命令
├── internal/
│   ├── config/                # YAML + env 配置（源凭据、间隔、时区）
│   ├── store/                 # schema 迁移 + 查询（events/media/sources/sync_state）
│   ├── sources/               # 每源一个适配器（见 §3 逐个方案）
│   │   ├── huozhi.go  mujian.go  diarum.go  zhichang.go
│   │   ├── dawarich.go  bilihistory.go  qiansi.go  shenshi.go
│   │   ├── qingye.go liuxia.go chaxin.go feixi.go whoami.go
│   │   ├── immich.go           # 照片（Dawarich photos 之外的直连补充，可选）
│   │   └── ingest.go           # 可选补录通道（无 Dawarich 信号时手动/快捷指令补点，P2）
│   ├── normalize/             # 归一化：时间(unix UTC+local_date)、坐标(GCJ-02→WGS-84)、
│   │                          #   金额(分+currency)、分类映射、事件类型映射
│   ├── scheduler/             # 每源独立间隔 + 失败退避 + 水位游标
│   ├── api/                   # REST：timeline / events / sources / media / stats / ingest
│   ├── media/                 # 媒体代理与缓存（前端不直连各源，避免 token 外泄）
│   └── mcp/                   # 只读 MCP（可选，Phase 4）
└── web/                       # SvelteKit SPA
```

**数据流**：`各源 API/导出 → sources 适配器 → normalize → events 表 → REST API → 前端时间轴`；媒体不落地为真相源，仅索引 + 代理转发（可选本地缓存）。

## 3. 数据源接入方案（逐个）

统一约定：所有适配器实现 `Fetch(ctx, since time.Time) ([]RawEvent, error)`，由 scheduler 按间隔调用；凭据一律走环境变量/配置文件引用，**不硬编码**。

### 3.1 六大核心源

#### huozhi（记账）— 15 分钟增量

- **接入方式**：`GET /api/transactions?start_date=<last_sync>&end_date=<today>&page_size=200` 翻页，`Authorization: Bearer <JWT>` 或 `X-API-Key`。生成专用 API Key（`POST /api/api-key/generate`）仅用于观复。
- **频率**：15 分钟（`tx_date` 有索引，增量便宜）。
- **字段映射**：`tx_date`(本地时区 datetime) → `occurred_at` + `local_date`；`amount`(分) → `amount_minor`；`type` → event_type（`expense`→支出、`income`→收入、`transfer`→转账、`reimburse`→报销）；`category_name` → `category`（经分类映射表归一）；`merchant`/`location` → 摘要/地点文本；`images` → media 索引（经 `/api/uploads/<key>` 代理）。
- **注意**：JSON 金额单位为「元」而库内为「分」，以接口返回为准；API Key 无只读 scope（与 JWT 等价全权），观复只发 GET；`/api/public/bills` 不过滤软删除，**不采用**，走标准列表接口。
- **深链**：`https://<huozhi 域名>/transactions/{id}`（域名按实际部署填）。

#### diarum（日记）— 30 分钟增量

- **接入方式**：公开 API `GET /api/v1/diaries?start=<date>&end=<date>`，`?token=<API token>`（设置页生成）。或 JWT。
- **频率**：30 分钟。
- **字段映射**：`date` → `local_date` + `time_precision=day`（全天事件）；`content`(HTML) → `detail_json`（前端渲染摘要）；`mood`(1-5) → 摘要徽标；`tags` → `tags`；`weather`/`city`/`temp_min/max` → detail_json。
- **深链**：`https://<diarum 域名>/?date=<date>`。

#### mujian（演出）— 30 分钟增量

- **接入方式**：`GET /api/records?start=<last_sync>&end=<today>&limit=200&offset=` 翻页，`?token=<MJ_AUTH_TOKEN>`。票根照片：`GET /api/records/{id}/photos` → `/uploads/<key>` 代理。
- **频率**：30 分钟。
- **字段映射**：`date`(unix 秒) → `occurred_at`；`name`+`category_name` → 标题；`address` → `location_name`；`coordinate`(GCJ-02) → **WGS-84 转换后**入库（转换算法参考 mujian `backend/internal/ics/ics.go:251`）；`rating`/`price`/`pay_price` → detail_json；封面 `cover`/`cover_thumb` → media。
- **注意**：单令牌全权（无只读 token），观复只发 GET；S3 模式下图片 URL = `s3_public_url + "/" + key`，需在源配置里记录 `s3_public_url`。
- **深链**：`https://mujian.example.com/records/{id}`（以实际为准）。

#### zhichang（健康指标）— 30 分钟增量

- **接入方式**（读取端无鉴权，内网直连；若跨机则加反代 + token）：
  - 天级：`GET /api/daily?metrics=<step_count,heart_rate,...>&from&to`
  - 原始样本（关键指标）：`GET /api/samples?metric=heart_rate&from&to&limit=1000`
  - 睡眠：`GET /api/sleep?from&to`；运动：`GET /api/workouts?from&to`
  - 单日全貌：`GET /api/summary?date=`
- **频率**：30 分钟（HAE 本身在 iPhone 侧定时推送，这里只是读库）。
- **字段映射**：每个「日×指标」生成一条 event（`event_type=health_metric`，`time_precision=day`），或聚合为当日一条 `health_day` 事件 + `detail_json` 存全部指标——**推荐后者**（避免时间轴被几十个指标刷屏；前端展开看详情）。睡眠/运动各一条事件。
- **深链**：`http://127.0.0.1:18788/?date=<date>`。

#### dawarich（到访地点）— 30 分钟增量（实例与 key 已实测，2026-10-15）

- **实例事实**（来自 Dawarich 官方文档与源码 `Freika/dawarich` `config/routes.rb`、`app/controllers/api/v1/*`，以及 `https://dawarich.example.com` 实测）：Rails + PostGIS 应用，API key 在 Account → API access 页生成，**一个 key 通行整个 `/api/v1`（含写端点，无只读 scope，需自行保管；可随时吊销重建）**。
- **认证**：`Authorization: Bearer <DAWARICH_API_KEY>`（官方文档明确 MCP 端拒绝 URL 传 key；API 控制器历史上两种都收，一律用 Header）。
- **为什么 key 是必须的（2026-10-15 源码核实，无零 key 替代）**：Dawarich 确实有免认证的公开分享端点 `GET /api/v1/shared/:id/points|photos`（`Api::V1::Shared::BaseController` 只按 share-link UUID 鉴权，非 family_only 且无 magic phrase 时公开），但它满足不了观复的按天增量需求：
  1. `shared/:id/points` 的时间范围是**创建分享时写死的** `settings['start_date']~['end_date']`（按用户时区整天），无法按天动态查询——今天的轨迹不在上周创建的分享范围内；
  2. 只返回 `[[lon,lat,ts],…]` 原始点（上限 10000 采样），**没有 visits 语义**（地名、停留时长、confidence），观复得自己聚类 + 反解地名，质量远低于 Dawarich 服务端 visits 检测；
  3. `shared/:id/photos` 仅返回有 GPS 的照片（且依赖 Immich 集成 + 分享开关），不能替代 Immich 直连（§3.2 已定直连）。
  - **结论：visits/timeline 必须走 Bearer key**；share link 仅作极端降级备选（一次性拉历史轨迹），不进入主链路。
- **实测数据现状（2026-10-15 21:40，key 由用户提供）**：
  - `GET /api/v1/health` → ok；`/api/v1/users/me` → 郁飞（id=1，`i@example.com`，**时区 Asia/Shanghai**——时间换算按此）。

## 4. 统一数据格式与核心数据模型

### 4.1 统一约定

| 维度 | 约定 | 说明 |
|---|---|---|
| 时间 | `occurred_at` unix 秒（UTC）+ `local_date`（`YYYY-MM-DD`，Asia/Shanghai 派生）+ `time_precision`（`second`/`minute`/`day`） | 日期型事件（日记/账单/健康）按 `day` 处理，前端归入「全天」分区 |
| 标识 | 全局 ID = `{source_id}:{external_id}`（如 `huozhi:12345`），`(source_id, external_id)` 唯一索引保证幂等 | 重跑同步不重复 |
| 坐标 | 一律 WGS-84；mujian 入库前 GCJ-02→WGS-84 | 地图统一渲染 |
| 金额 | `amount_minor`（分，bigint）+ `currency` | huozhi 库内即分；无金额事件为 NULL |
| 分类 | `category` 归一化分类 + `category_map(source_id, source_category, norm_category)` 映射表 | 跨源统计口径一致 |
| 媒体 | `media` 表索引 + 观复代理端点 `/api/v1/media/{id}`（302/流式） | 前端永不直连各源，token 不外泄 |
| 深链 | `sources.deep_link_template`（如 `https://mujian.example.com/records/{id}`） | 卡片「查看原件」跳回源应用 |

### 4.2 Schema（SQLite DDL，落地即用）

```sql
CREATE TABLE sources (
  id TEXT PRIMARY KEY,              -- 'huozhi' | 'mujian' | 'diarum' | ...
  name TEXT NOT NULL,
  kind TEXT NOT NULL,               -- poll | push | import
  base_url TEXT,
  auth_type TEXT,                   -- none | token | api_key | jwt | cookie
  credential_ref TEXT,              -- env 变量名，不存明文
  sync_interval_s INTEGER DEFAULT 1800,
  deep_link_template TEXT,
  extra_json TEXT,                  -- 源特有配置（如 s3_public_url、person_id）
  enabled INTEGER DEFAULT 1,
  last_sync_at INTEGER,
  last_status TEXT,                 -- ok | error
  last_error TEXT,
  created_at INTEGER DEFAULT (unixepoch())
);

CREATE TABLE events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id TEXT NOT NULL REFERENCES sources(id),
  event_type TEXT NOT NULL,         -- expense income transfer diary performance
                                     -- health_day sleep workout photo location_visit
                                     -- cycle_log video_watch social_event ...
  external_id TEXT NOT NULL,        -- 源内主键
  occurred_at INTEGER NOT NULL,     -- unix 秒 UTC
  local_date TEXT NOT NULL,         -- YYYY-MM-DD（Asia/Shanghai）
  time_precision TEXT DEFAULT 'second',
  title TEXT,
  summary TEXT,
  detail_json TEXT,                 -- 源特有字段原样保留
  amount_minor INTEGER,
  currency TEXT,
  category TEXT,
  tags_json TEXT,
  location_name TEXT,
  latitude REAL, longitude REAL,    -- WGS-84
  UNIQUE(source_id, external_id)
);
CREATE INDEX idx_events_date ON events(local_date);
CREATE INDEX idx_events_type ON events(event_type);
CREATE INDEX idx_events_occurred ON events(occurred_at);

CREATE TABLE media (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id INTEGER NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  kind TEXT,                        -- photo | cover | ticket | attachment
  origin_url TEXT NOT NULL,         -- 源访问 URL（可带 token，仅服务端可见）
  cache_path TEXT,                  -- 可选本地缓存
  hash TEXT,
  taken_at INTEGER,
  sort INTEGER DEFAULT 0
);
CREATE INDEX idx_media_event ON media(event_id);

CREATE TABLE sync_state (
  source_id TEXT PRIMARY KEY REFERENCES sources(id),
  cursor TEXT,                      -- 游标（日期/页码/id）
  watermark INTEGER                 -- 最后同步时间
);

CREATE TABLE category_map (
  source_id TEXT NOT NULL,
  source_category TEXT NOT NULL,
  norm_category TEXT NOT NULL,
  PRIMARY KEY (source_id, source_category)
);
```

## 5. 前端展示结构

### 5.1 路由与布局

```
/                今日时间轴（默认）
/day/:date       历史某日
/month           月视图（日历热力图 + 月统计）
/event/:id       事件详情（源字段全展开 + 原件深链 + 媒体）
/sources         数据源管理（启停、间隔、健康、手动同步）
/import          导入页（各源导出文件拖拽解析；兜底通道）
```

布局：**左栏迷你日历**（有数据日期打点，热力浓度）｜**中栏时间轴**｜**右栏当日摘要**（收支合计、指标 chips、事件分类计数）。移动端折叠为单栏 + 底部日期切换。

### 5.2 时间轴结构

- **「全天」分区**（置顶）：日记、记账、健康日汇总 —— `time_precision=day` 的事件。
- **时刻流**（按 `occurred_at` 倒序/正序可切换）：演出、B 站观看、照片、到访、社交事件、系统事件。
- **卡片渲染器按 `event_type` 注册**，每类一个 Svelte 组件：

| 事件类型 | 卡片形态 |
|---|---|
| `expense`/`income` | 金额（涨红跌绿）+ 分类图标 + 商家/备注 + 图片缩略 |
| `performance` | 封面图 + 剧种《剧名》+ 场馆 + 评分 + 「门票实付」徽标（来自 huozhi 关联） |
| `diary` | 心情 emoji + 正文前 3 行 + 标签 + 天气/气温 |
| `health_day` | 指标 chips（步数/心率/睡眠时长…）+ 展开看全量 + 迷你 sparkline |
| `photo` | 当日照片网格（懒加载 + 点击灯箱） |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 观复集中全部个人数据，单点失守即全泄 | 仅内网/本地部署；凭据走 env + 文件权限 600；媒体经代理不直连；敏感正文（日记）前端默认折叠；SQLite 文件纳入既有备份体系（docker-db-auto-backup 已支持） |
| 各源 API 变动导致同步失败 | 适配器层隔离 + `sources.last_error` 可见 + ntfy 告警；每源独立退避，互不影响 |
| API Key 全权风险（huozhi/mujian/Dawarich） | 观复只发 GET；Key 单独生成、可即时吊销；P2 推动各源加只读 scope |
| 时区混乱（tx_date 本地时间 vs unix vs 日期字符串） | 统一 `occurred_at`(UTC) + `local_date`(Asia/Shanghai) 双字段；入库时一次性换算 |
| 坐标混乱（mujian GCJ-02 vs Dawarich GPS 原始坐标） | normalize 层统一转 WGS-84；Dawarich 坐标需实测确认基准（入库前抽样比对已知地点） |
| Immich key 权限不足 / 接口变动 | 已实测读取权限齐全（`asset.read/view/download/statistics`）；适配器按 §3.2 实测端点实现（search/metadata 按日 + buckets 月度分桶）；降级方案：Dawarich photos 端点或 mujian 票根 + qingye 照片日记顶上 |
| Dawarich 无历史数据或上报中断 | 接入前查 `points/tracked_months` 确认覆盖；visits 只收 `confirmed`；中断时启用 P2 ingest 补录 |
