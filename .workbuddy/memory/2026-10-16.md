## M4 首批增值源完成（commit fa2e267）

本人选定 M4 先做增值源，落地 qiansi + shenshi + liuxia 三源（其余 qingye/chaxin/feixi/whoami 待排期）。

**调研方法**：三个 Explore 子代理并行读各项目源码（qiansi/shenshi/liuxia），每条结论都带文件行号证据——收益很大，直接拿到字段级契约（含 JSON tag、指针可空、单位、时区）。

**契约要点（源码核对 + stub 端到端实测）**：
- **qiansi**（默认端口 **:8080**，规划文档曾误记 8898）：`/api/v1/events/`、`/api/v1/transactions/`、`/api/v1/anniversaries/` 三端点**均返回裸数组**（无 data 包装）；起止参数是 `from`/`to` 且强校验 `YYYY-MM-DD`（RFC3339 直接 400）；金额 `amount_fen` 是**分**、非空；事件 money 字段是分层投影（`gift_amount_fen/gift_direction` vs `expense_fen`）；纪念日接口**无参数无分页**，`next_date` 由服务端算好（农历/每年循环），必须按它投放而不是 `date`；`location` 与 `locations[]` 内容重叠，取 locations 数组避免「上海 · 静安 · 上海 · 静安」。
- **shenshi**（:8787）：`/api/tasks` 的 `from`/`to` 过滤 **due_date 不是完成日**，且**无 offset 分页**（只有 LIMIT）→ 增量只能「按完成时间倒序拉最近 N 条 + 客户端按 `completedAt[:10]` 截断」；`completedAt` 是**本地时区 RFC3339**；`/api/reviews/{date}` 缺记录返回 200+空壳；习惯看板 `includeArchived=1` 是"含归档"（任务侧 `archived=1` 语义相反）。
- **liuxia**（:8080）：`/api/export?format=json&start&end` 无记录时输出**字面量 null**；`quality`/`aod` 可空 float；表唯一键 `(city,date,event_type,model)` 一天最多 4 条 → 按 (城市,日期) 聚合。

**设计取舍**：
- 幂等键加表前缀（`ev:`/`tx:`/`ann:`/`task:`/`review:`/`habit:`/`sky:`），避免跨表 ID 撞车。
- qiansi 只收 `kind=gift`（礼金），loan/expense 与货殖记账语义重叠不入轴。
- liuxia cursor **固定为"今天"**（不随未来日期推进）：未来预报段每轮重拉（预报会修正），过去段靠重叠窗口兜补录——这与其它源的"cursor=已同步到的最大日期"语义不同，代码里写明了。
- 全天事件聚合（habit_check 一天一条、sky_forecast 一天一条）避免时间轴被高频事件淹没。

**顺手修掉一个既有口径不一致**：`model.NewDayEvent` 注释写「时刻固定为当地中午」，实现却是 `ParseInLocation` 得到的 **00:00**；而 zhichang/dawarich 的日汇总自己构造的是 12:00。结果是全天卡在时间轴上挤到最前。已改为统一当地中午（局部能验证：事件 local_time 从 00:00 变 12:00）。

**验证**：8 例新单测（翻页/鉴权头/RFC3339 归日/null 容错/辅助函数）+ 三源 Python stub 端到端同步 7 条事件入库 + Playwright 截图（金额红绿、习惯 chips、7 张卡、零 console 错误）。**重要教训**：`NewDayEvent` 这类"注释即契约"的公共构造函数，改动会影响全部调用的源，必须在 stub 端到端里核对 `local_time` 而不是只看单测绿。
